# 公網部署:如何設置訪問密碼

未設訪問密碼時,面板只接受**本機**(`127.0.0.1` / `::1`)的請求,區網與公網請求一律拒絕,以防他人搶先設置密碼鎖死你的面板,或在你設密碼前直接操作面板。

如果你從區網或公網的瀏覽器直接打開頁面,會看到提示:

> 未设访问密码时仅允许本机(127.0.0.1 或 ::1)访问。请先在本机浏览器设置密码,或以 AUTH_PASSWORD 环境变量预设密码后重启服务

有兩種方式解決,任選其一。

---

## 方式一:環境變量預置密碼(最簡單,推薦)

在 `.env` 文件(或 Docker / 系統環境變量)裡設置 `AUTH_PASSWORD`:

```bash
# 編輯服務器上的 .env (通常在項目根目錄或 backend/ 下)
AUTH_PASSWORD='你的密碼'
```

然後重啟服務。啟動時會自動:
1. 讀取 `AUTH_PASSWORD`
2. 用 PBKDF2 哈希後寫入 `auth.json`(`chmod 600`,只存哈希不存明文)
3. **之後這個環境變量就不再被讀取** —— 是一次性的初始化

設完後即可用公網地址 + 這個密碼正常登錄。後續改密碼請用頁面 UI(`設定 → 帳戶安全`),不受環境變量影響。

### 注意事項

- **密碼至少 6 位**,否則會被跳過並記一條 warning 日誌
- **僅在未設過密碼時生效**。已設過密碼後,改這裡不會覆蓋(避免重啟時重置你在 UI 改的密碼)
- 密碼建議使用單引號包裹，避免 Docker Compose 插值 `$VAR`；啟動時也會從只讀掛載的原始 `.env` 初始化，兼容已有的未加引號配置
- `.env` 文件權限保持 `600`,**不要提交到 Git**
- 明文密碼只存在於 `.env` / 環境變量中,落盤的是哈希,安全性等同 `auth.json`

### 重置密碼(忘密碼時)

如果忘了密碼想重置:刪除或清空 `data/user_data/auth.json`,重啟服務,會回到"未設密碼"狀態,此時 `AUTH_PASSWORD` 會重新生效。

```bash
# 停服後執行, 清空後重啟
rm data/user_data/auth.json
```

## 方式二:SSH 端口轉發

不用改配置,在你**自己電腦**的終端執行(不是服務器上):

```bash
ssh -L 3018:127.0.0.1:3018 用戶名@服務器IP
```

例如服務器是 `123.45.67.89`、用戶名 `root`、面板端口 `3018`:

```bash
ssh -L 3018:127.0.0.1:3018 root@123.45.67.89
```

保持這個 SSH 連接**不要關**,然後在**自己電腦的瀏覽器**打開:

```
http://127.0.0.1:3018
```

此時後端看到的客戶端 IP 是 `127.0.0.1`(本機),能通過校驗,正常顯示設置密碼界面。

**設完密碼後**,SSH 連接可以斷開 —— 密碼已存進服務器,之後直接用公網地址 + 剛設的密碼訪問即可。

### 端口說明

上面的 `3018` 是默認端口。如果你用 `PORT` 環境變量改過端口(比如 `PORT=8080`),兩處都要替換:

```bash
ssh -L 8080:127.0.0.1:8080 root@123.45.67.89
```

## 原理說明

- **為什麼只限本機?** 能連到服務器的人(包括同一區網的其他裝置)都能訪問 URL。如果不限制,他人可以在你之前打開頁面、設置一個密碼把面板鎖死,或在你設密碼前直接操作面板。
- **本機如何判斷?** 客戶端 IP 必須是 `127.0.0.1` 或 `::1`,而且請求的 Host 必須是 `localhost`、`127.0.0.1` 或 `[::1]`(可帶端口)。Host 檢查用來擋 DNS rebinding:惡意網站把自己的網域解析到 `127.0.0.1` 時,瀏覽器送出的 Host 仍是該網域。
- **跨來源請求:** 面板只接受同源請求。瀏覽器送出的 `Origin` 與請求的 Host 不同時,`/api/` 一律回 403,其他網站無法借你的瀏覽器操作面板。
- **SSH 轉發為什麼有效?** `-L` 把本機端口通過 SSH 隧道轉發到服務器的 `127.0.0.1`,等同於在服務器本地訪問,客戶端 IP 變成 `127.0.0.1`,通過校驗。
- **反向代理注意:** 後端不自行解析 `X-Forwarded-For`,客戶端 IP 由 uvicorn 決定:只有直連來源列在 `FORWARDED_ALLOW_IPS`(預設 `127.0.0.1`)時,才採用 `X-Forwarded-For` 最右側不受信任的位址。反代與面板不在同一台機器,或面板跑在 Docker 內時,要把反代連進來的位址設進 `FORWARDED_ALLOW_IPS`,否則登入限流會把所有人算成同一個來源;同時面板端口只能讓反代連到(例如 Docker 以 `HOST=127.0.0.1` 只綁本機),否則直連面板的人也會被當成反代,可以偽造 `X-Forwarded-For`。反代也要原樣轉發瀏覽器送來的 Host(含端口;Nginx 用 `proxy_set_header Host $http_host;`,不要用不帶端口的 `$host`),否則瀏覽器的 `Origin` 與 Host 不符,請求會被拒絕。
- **Docker 內的 `FORWARDED_ALLOW_IPS` 怎麼填:** 反代在主機上時,容器看到的來源是 compose 網路的閘道,不一定是 `docker0` 的 `172.17.0.1`。先 `docker compose up` 一次,再用 `docker network inspect <專案名>_default --format '{{range .IPAM.Config}}{{.Gateway}}{{end}}'` 查出閘道位址填入(專案名預設是 compose 檔所在目錄名,可用 `docker network ls` 確認);反代也是同一個 compose 網路裡的容器時,改填反代容器在該網路內的位址。

## 兩種方式怎麼選

| | 環境變量 | SSH 轉發 |
|---|---|---|
| 操作 | 改一行配置 + 重啟 | 一條 ssh 命令 |
| 需要改配置 | 是 | 否 |
| 適合 | Docker / 自動化部署 / 不熟 SSH | 臨時設密碼 / 能 SSH 到服務器 |
| 後續改密碼 | UI(`設定 → 帳戶安全`) | 同左 |

推薦**方式一(環境變量)**,一次配置即可。

> **Docker 部署必須用方式一。** 主機瀏覽器連進容器時,容器看到的來源是 Docker 網路的閘道位址(`172.x.x.x` 之類),不是 `127.0.0.1`;所以即使在同一台電腦打開 `http://localhost:3018`,未設密碼時也會被拒絕,SSH 轉發到主機的 `127.0.0.1` 也一樣。請先在 `.env` 設好 `AUTH_PASSWORD` 再啟動容器。
